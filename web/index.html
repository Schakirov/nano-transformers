The architecture

A decoder-only transformer — GPT in miniature. It reads a sequence of integer tokens and predicts the next one at every position. That single ability expresses all three tasks.

The forward pass, in full

tokens ─► token embedding + positional embedding      wte[id] + wpe[pos]
       ─► Block × n_layer
       ─► final LayerNorm
       ─► unembed  → logits over the vocabulary       x @ head_w

Block (pre-norm residual):
   x = x + Attention( LayerNorm(x) )
   x = x + MLP( LayerNorm(x) )

Causal self-attention (per head):
   Q,K,V = split( x @ attn_w )
   A     = softmax( Q·Kᵀ / √d  +  causal_mask )    ← future is masked to −∞
   out   = A · V

Why "predict the next token" is enough

Each task is just a sequence with an answer region we score:

sort   4 5 7 2 2 4  >  2 2 4 4 5 7
add    8 8 + 6 8 =  6 5 1     (answer least-significant first)
shapes [64 pixel tokens] =  box

Symbolic, arithmetic, and visual inputs all become token ids. The model never knows which modality it is looking at.

The gradient that matters most

Backprop through a matrix multiply C = A @ B is just two more matrix multiplies. Internalise this one rule and the rest of nanograd.py reads easily:

  forward:   C = A @ B
  backward:  dA = dC @ Bᵀ        dB = Aᵀ @ dC

Open Read the code → nanograd.py and find __matmul__; that is the exact code, four lines, with the broadcasting handled by one helper.

What to look for in matmul

The tiled kernel's inner loop is the heart of all of deep learning.

  • .shared (PTX) / STS,LDS (SASS) — staging a tile into fast on-chip memory and reading it back, instead of hitting slow DRAM 16× more.
  • bar.sync / BAR.SYNC — the __syncthreads() barrier that makes the 256 threads of a block agree the tile is fully loaded.
  • fma.rn.f32 / FFMA — one fused multiply-add: acc += a*b, the only arithmetic that actually matters, run billions of times.

What to look for in softmax

One warp (32 threads) cooperatively reduces one row — with no shared memory at all.

  • shfl.sync.down.b32 / SHFL.DOWN — the warp shuffle: lane i reads a register directly out of lane i+offset. Five of them reduce 32 values to one.
  • No bar.sync in the reduction — threads in a warp run in lockstep, so they need no barrier to exchange registers. This is the GPU's most distinctive trick.
  • MUFU.EX2 (SASS) — the special-function unit computing exp in hardware.
